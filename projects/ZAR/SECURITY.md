# Security Policy

## Reporting a vulnerability

Do not publish exploitable details, private keys, seed phrases, passwords, or personal data in a public issue. Use the repository owner's private vulnerability-reporting channel if available. If no private channel is configured, contact the maintainers through an established private channel and share only the minimum details needed to reproduce the issue.

## Scope

Relevant issues include unauthorized minting or burning, cap bypass, ledger accounting errors, compromised controller authority, insecure upgrades, key exposure, and incorrect transaction authorization.

## Disclosure

Allow maintainers time to reproduce, assess, and fix a vulnerability before public disclosure. Security fixes must include regression tests and must not expose secret material.
