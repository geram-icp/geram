# ZAR Public Claims and Evidence Register

## Rule

Public claims about fiat equivalence, backing, redemption, listings, bank acceptance, security audits, adoption, performance or production deployment require current, reviewable evidence. Aspirations must be labeled as aspirations.

## Claims that are not established by this repository

- A legally enforceable 1:1 exchange or redemption relationship with the South African rand.
- Reserve backing or independent reserve attestations.
- Acceptance by all or most international banks.
- Acceptance or listing by any particular centralized or decentralized exchange.
- Broad adoption or rapidly growing live usage.
- Production deployment or independent security audit.
- Guaranteed speed, savings, safety, price stability or financial returns.

## Evidence needed before publishing a claim

| Claim type | Minimum evidence |
|---|---|
| 1:1 rand relationship | Legal issuer and holder rights, redemption terms, reserve model and independent ongoing verification where applicable |
| Bank/payment acceptance | Named provider confirmation, signed agreement or official public listing, scope and date |
| Exchange listing | Official exchange asset page or listing announcement, supported network and deposit/withdrawal status |
| Production deployment | Canister IDs, network, source commit, Wasm hash and independent on-chain verification |
| Supply cap | Source review and adversarial tests covering every mint path and upgrades |
| Security audit | Published report from the named auditor, scope, date and remediation status |
| Adoption growth | Defined metric, time period, methodology and reliable source data |
| Performance claims | Reproducible benchmark, environment, sample size and limitations |

## Review process

Before publishing a material claim, record the claim, evidence URL or file, owner, review date, limitations and approval. Remove or update stale claims when evidence expires or the integration changes.
